01

Clear boundaries create trustworthy infrastructure.

KudiRail coordinates payment intent and records evidence. It never becomes the signer, wallet, privacy pool, bank, or settlement provider.

No server signing authority

The wallet owns simulation, proof creation, signing, and submission. KudiRail produces intent, never authorization.

Minimal execution data

Manifests omit worker names and contain only stable identifiers, recipients, amounts, and payment metadata.

Evidence over assumption

Finalization requires a successful receipt and an event from the configured STRK20 pool.

Safe retry behavior

Idempotent creation and guarded recovery prevent blind duplicate payroll submissions.

Organization payroll controls

Pause new payouts, cap each pay run, and protect a reserve without giving KudiRail signing authority.

Privacy has an explicit edge.

Shielding and intentional exits are public. Privacy begins inside STRK20. Bank-recipient data and provider state sit outside the private-transfer boundary.

05

Local settlement stays separately accountable.

Paycrest is an optional offramp adapter. Provider status is provider evidence—not proof invented by KudiRail.

StatusStageMeaning
initiatedAwaiting depositThe order exists; funds are not attributed.
depositedDetectedThe settlement deposit was recognized.
pendingDeliveringFiat delivery is in progress.
validatedDeliveredThe provider confirmed delivery.
refundingReturningA detected deposit is being returned.
refundedReturnedVerify the return transaction before closure.
expiredUnattributedPaycrest says no deposit was detected before expiry.

KudiRoll recovery states

  1. Payment submitted means the wallet attempt or transaction hash is durably recorded.
  2. Awaiting Paycrest detection means Starknet proves the exact pool-to-order transfer but Paycrest has not attributed it yet.
  3. Reconciliation required blocks duplicate payment and prepares provider evidence.
  4. Refunding, Refunded, and Completed mirror provider progress while the export keeps provider and chain evidence separate.

Successful transfer, expired provider order

  1. Verify receipt, block time, token, amount, destination, and STRK20 pool participation.
  2. Compare provider amount paid, amount returned, hash, update time, and logs.
  3. Request documented reindexing for the transaction and assigned address.
  4. If zero paid and returned remain, request manual attribution. Never resend to an expired address.
